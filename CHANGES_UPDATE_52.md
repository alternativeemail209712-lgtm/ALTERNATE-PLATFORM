Only the word data, the lexicon builder and the word loader changed.

| Accepted guesses (bundled, works offline) | Update 51 | Update 52 |
|---|---|---|
| Indonesian | ~47,500 | **~96,600** |
| Malay (Malaysia) | ~47,400 | **~95,900** |
| Secret words (answers), each | ~8,100 | ~8,100 (unchanged, strict) |

English is unchanged (370,000+).

## Two tiers - please read
* **Core tier (~47,000 per language):** roots written from knowledge of KBBI / Kamus Dewan usage plus regular affix forms of them.
* **Extended tier (~49,000 per language, new):** further regular affix forms (me-, di-, ber-, ter-, pe-an, per-an, ke-an, memper-, -kan, -i ...) of every root. This is what lifts the total above 80,000 so real derived words are not refused. **These forms are generated by grammar rules, not looked up in KBBI or Kamus Dewan**, so a share of them (I estimate a large minority) are regular-looking forms that no dictionary lists. They only affect which guesses are ACCEPTED. Secret words never come from this tier.
* To accept only the conservative list, set the environment variable `STRICT_WORDS=1`.
* No internet was available while building, so nothing was checked online against KBBI or DBP. For a verified list, use `node tools/import-wordlist.mjs id|ms yourlist.txt` and upload `data/`.

## Keeping the two languages apart
* Each language is built from its own roots. Any root listed in that language's reject file (the other language's spelling, e.g. mobil / sepeda / kantor for Indonesian-only, kasut / seluar / pejabat / universiti / aktiviti for Malay-only) gets NO derived forms, so `bermobil` is refused in Malay and `berkasut` in Indonesian.
* Words spelled the same in both (rumah, makan, kereta, kampung ...) work in both, as before. The mixed modes (EN+ID, EN+MS, MS+ID, all) still use each language's own list.
